# JS Tax Agent 인계

- UI·UX 적용 여부: 적용 / 화면 있음.
- 목적은 세목별 공식 근거와 적용 시점을 검토하고 가정별 세액을 비교하는 것이다.
- v0.4.0은 2026년 상속세·증여세 비교와 두 세목의 공식 근거 12개를 추가한다. 전체 공식 근거는 33개다. 릴리스의 기능 범위는 [v0.4 릴리스 노트](release-v0.4.md)에 기록한다.
- 상속세·증여세는 재산 평가와 합산·차감을 반영한 과세가액, 적용 한도를 확인한 공제·수수료를 직접 입력한다. 2026-11-04 승인 API로 법률·시행령·시행규칙과 두 세목의 회신·판례 후보를 수집했다. 각 세목 회신·판례 1건씩의 본문을 검증해 검색에 반영했다.
- 상속개시일·증여일을 입력하면 2026-01-01~2026-11-04 공식 연혁에서 대조한 시행본과 관련 부칙을 비교 화면에 표시한다. 날짜 조회에는 API 인증값이 필요 없다. 이후 조회 범위를 넓힐 때 중간 시행본과 개정문을 확인하고 새 날짜 경계를 검사한다.
- 상속세·증여세의 개정 추적은 법제처 본문에서 바뀐 조문을 찾아 답변과 비교 화면에 표시한다. 검토 전 수집 결과는 로컬에서 공유하며, 새 시행본을 검토하면 조문 연결과 계산 규칙, 기준 시행본을 함께 점검한다. OC를 Windows 계정에 암호화해 등록하면 로컬 앱에서 상속세·증여세를 사용할 때 당일 기록이 없는 경우 자동 수집한다.
- 호스팅 사이트와 수집 이력이 없는 로컬 실행은 릴리스에 포함한 법제처 확인 결과를 확인일과 함께 표시한다. 호스팅 확인 결과를 갱신하려면 검증한 수집 결과를 `public/data/transfer-law-review.mjs`에 반영하고 다시 배포한다.
- 상속세·증여세를 비교하기 전에 사전증여와 공제 이력, 상속의 분할일을 확인하는 입력 단계를 추가했다. 각 안의 공제 항목을 합산할 때 중복을 차단하고, 증여공제 이력이 있으면 직접 확인한 남은 한도를 적용한다. 이 입력값은 브라우저에서 처리한다.
- 결정: 법인세는 세무조정 후 과세표준을 사용한다. 부가세는 공제 여부를 확인한 매입세액을 직접 입력한다. 법령 개정과 원문 후보는 수집 후 사람 검토를 거쳐 계산과 검색에 반영한다.
- 검증: 데스크톱·모바일 기본 흐름과 세액 결과, 공식 근거 검색, 생성 AI 모의 응답을 확인했다. 2026-11-04 법제처 실데이터로 세 세목의 첫 수집과 법령 버전 대조를 완료했다. 추가 세목의 실제 생성 답변은 별도 검증이 필요하다.
- 설계: 키는 서버 환경에만 두고 웹 입력·공개 소스·배포 번들에 포함하지 않는다. 호스팅의 개인 접근 권한을 유지한다.
- 실행: 프로젝트 폴더에서 `node server.mjs`. 승인된 로컬 설정을 읽을 때는 `node --env-file-if-exists=.env server.mjs`.
- 관련 문서: spec.md, plan.md, todo.md, design.md, sources.md, validation.md, law-discovery.md, api-key-setup.md.
- 계정별 설정·운영 진단의 상세 인계는 Git에서 제외된 `outputs/hosting-handoff-private.md`와 `outputs/hosting-validation-private.md`에 로컬 전용으로 보관한다.
- 다음: 첫 수집을 기준으로 다음 실행의 버전 차이를 확인하고, 개별 회신·판례와 시행예정본을 활용할 때 원문·조문·부칙을 확인한다. 생성 AI 실검증은 무료 크레딧 조건이 충족될 때 진행한다.
- 수집: Windows의 기본 DNS 조회가 실패할 때 수집기에서만 DNS-over-HTTPS를 사용한다. Windows PowerShell에서 Node의 절대 경로로 수집기를 실행했다. 인증값은 숨김 입력으로 받아 실행 세션에서 정리했다. 원본 결과와 운영 진단은 Git에서 제외한 `outputs/`에 둔다.
