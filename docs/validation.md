# 검증 기록

## 상속세·증여세 비교 전 확인

- 데스크톱에서 사전 확인 누락 시 계산을 막고 빠진 입력으로 이동하는 것을 확인했다. 한 안의 공제 중복과 일괄공제·기초공제의 동시 입력을 차단했고, 중복을 삭제하면 기준안과 비교안에 동일한 일괄공제를 각각 적용해 정상 계산했다.
- 배우자 상속재산 분할일의 누락과 상속개시일보다 빠른 입력을 차단했다. 날짜를 바로잡으면 계산했고, 상속개시일을 바꾸면 사전증여와 공제 이력을 다시 확인하도록 했다.
- 390px 모바일에서 기존 증여공제가 있는 경우 남은 한도 초과를 차단했다. 공제액을 두 안 모두 남은 2천만원으로 수정하면 산출세액은 각각 1,600만원과 800만원이었다. 가로 스크롤은 발생하지 않았다. 자동 검사 49개가 통과했다.

## 상속세·증여세 개정 영향 표시 (2026-11-04)

- 승인된 OC로 현행 본문 조회와 JSON 판독을 확인했다. 이 수집에서 새 시행본은 0건이었다.
- 모의 제26조 개정으로 두 세목의 기본세율·누진공제와 답변 근거가 표시되고, 과세최저한과 증여재산공제에는 표시되지 않는 것을 확인했다. 재수집 시 표시 유지, 부칙 변경 안내, 본문 실패 시 미완료 안내를 검사했다.
- 자동 검사 46개를 통과했다. Windows에서 시험 문자열로 OC 파일의 암호화, 교체, 복호화를 확인했다. 당일 기록이 없는 시험 환경에서 동시 요청을 보냈을 때 수집 프로세스가 한 번만 실행되고 두 세목에 같은 결과가 표시되는 것을 확인했다. 실제 OC 등록과 본문 재조회도 확인했다.

## 상속개시일·증여일에 따른 시행본과 부칙 (2026-11-04)

- 법제처 수집의 연초·현재 결과에 국가법령정보센터 연혁을 대조해 법률·시행령·시행규칙의 2026년 11월 4일까지 시행본을 확인했다. 1월 1일에 시행 중이던 2025년 시행령·시행규칙과 2월 27일·9월 18일 시행령도 포함했다. [법률 개정문](https://law.go.kr/LSW/lsRvsDocListP.do?chrClsCd=010202&lsId=001561&lsRvsGubun=all) · [시행령 개정문](https://law.go.kr/LSW/lsRvsDocListP.do?chrClsCd=010202&lsId=003814&lsRvsGubun=all) · [시행규칙 개정문](https://law.go.kr/LSW/lsRvsDocListP.do?chrClsCd=010202&lsId=007388&lsRvsGubun=all)
- 데스크톱에서 상속개시일 2월 26일·27일의 시행령과 부칙 전환을 확인했다. 모바일에서 증여일 9월 30일·10월 1일의 시행령과 별도 신고일 기준 부칙, 확인 범위 밖 안내, 세목별 날짜 유지와 가로 스크롤 없음을 확인했다. 자동 검사 45개가 통과했다.

## 상속세·증여세 법제처 실수집과 원문 검증 (2026-11-04)

- 승인된 OC로 검색어별 최대 첫 페이지를 수집했다. 상속세는 회신 193건·판례 196건, 증여세는 회신 200건·판례 119건이다. 세목 간 중복까지 제거하면 회신 352건·판례 301건이다. 결과는 Git 제외 대상인 `outputs/law-discovery-inheritance.json`과 `outputs/law-discovery-gift.json`에 저장했다.
- 두 세목에서 2026-01-02 기준 법률·시행령·시행규칙과 2026-11-04 시행본을 대조했다. 법률은 2026-01-02 시행본으로 같았고, 시행령은 2026-10-01, 시행규칙은 2026-03-20 시행본으로 바뀌었다. 조회 응답에 시행예정본은 없었다. [법률](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=276123) · [시행령](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=290845) · [시행규칙](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=284609)
- 각 세목에서 회신과 판결을 1건씩 검증해 역사적 참고 사례로 반영했다. 수집 목록과 원문의 문서번호·생산일·선고일을 맞추고 [원문 목록](sources.md)에 반영 범위를 기록했다.
- 브라우저에서 배우자 상속공제 현행 분할기한과 과거 회신·판례가 구분되는 것을 확인했다. 390px 모바일 뷰에서 자녀 대여금 채무면제 회신과 비교 화면의 수집일 기준 시행본 세 개를 확인했다. 자동 검사 43개가 통과했다. 실제 생성 AI 호출은 진행하지 않았다.

## 상속세와 증여세 계산기 추가 당시 검증 (2026-11-04)

- 전체 자동 검사 42개를 통과했다. 과세표준 50만원 경계와 누진구간, 세목별 근거 검색과 모의 생성 요청, 정적 빌드와 Worker 번들을 확인했다. 처음에는 Windows 샌드박스의 상위 폴더 조회 제한으로 Worker 번들 검사가 실패했다. 동일 명령을 권한 검토 후 다시 실행해 통과했다.
- 데스크톱 브라우저의 상속세 예시에서 산출세액 5,000만원과 3,000만원, 상속개시일 입력과 법령 연혁 안내를 확인했다. 모바일 390px에서 증여세 1,000만원과 500만원, 증여재산공제 답변, 상속세 자료 3개 필터를 확인했다. 모바일 비교와 질문 화면에 페이지 가로 스크롤이 없었다.
- 2026년 11월 4일 확인한 시행본에서 과세표준, 최저한과 세율을 대조했다. [상속세 제25조](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029615619) · [제26조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1027435947) · [증여세 제55·56조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1021869421)
- 계산기 추가 단계에서는 API 실수집과 실제 생성 AI 요청을 진행하지 않았다.

## v0.3 (2026-11-04)

- 전체 자동 검사 38개 통과. 2025년 종합소득세 회귀와 법인세 누진구간 경계, 부가세 부호와 입력 오류, 세목별 검색·사례 분리, 모의 생성 AI, 시행일과 예정본 분리 및 모의 페이지 수집을 확인했다.
- Windows 일반 실행 환경에서 정적 및 Sites Worker 빌드 성공. Windows 샌드박스에서는 esbuild가 상위 폴더를 읽지 못해 동일 명령을 일반 실행 환경에서 다시 수행했다.
- 브라우저 데스크톱에서 법인세 기본세율 답변에서 A/B 계산으로 이동했다. 과세표준 2억5천만원과 1억8천만원은 각각 3천만원과 1천8백만원이었다.
- 390×844에서 부가세 300만원 납부와 200만원 환급, 음수 입력 오류 후 필드 포커스, 보관함 필터, 기준일 범위 밖 차단, 세목별 입력 보존을 확인했다. 문서 폭은 375px로 가로 넘침이 없었다.
- 부가세 메모에서 거래 공급일, 세목, 환급 금액, 차이, 국세청 원문을 확인했다. 법인세와 부가세 국세청 질의회신·대법원 판결의 원문과 식별자, 생산·선고일 및 적용 한계는 sources.md에 기록했다.
- 새 세목의 실제 생성 AI는 미검증이며 외부 생성 API 요청을 보내지 않았다.
- GitHub v0.3.0 태그의 두 원격 검사가 통과했다. 릴리스 ZIP을 새 폴더에 풀고 키와 의존성 없이 서버·계산 테스트 13개를 실행했다. 릴리스의 ZIP SHA-256이 로컬 파일과 일치했다.
- 개인용 사이트의 새 버전 게시가 완료됐다. 로그인 전 접근 차단과 소유자 로그인 후 v0.3·공식 자료 21개·부가세 납부/환급 결과를 확인했다.
